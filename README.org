#+title: git-bug.el — Magit sections for the git-bug bug tracker

Adds a collapsible "Bugs" section to =magit-status= buffers listing the
bugs of the [[https://github.com/MichaelMure/git-bug][git-bug]] distributed bug tracker, which stores them in the
repository's own =refs/bugs/*= references.

* Usage

Add the section inserter to the status sections hook:

#+begin_src emacs-lisp
(add-hook 'magit-status-sections-hook #'git-bug-insert-status-bugs 100)
#+end_src

The section always shows the listed count over the total count.
Every bug is a collapsible section; expand it to load labels,
description and comments.
Headings are laid out in columns: short id, status, title, labels,
reply count and age.
Every column is as wide as its widest cell and empty columns are
dropped, so the labels of all bugs line up.
Bug bodies are fontified as Markdown with the builtin
=markdown-ts-mode= when its tree-sitter grammars are installed;
Markdown markup symbols are then hidden and links stay clickable.

** Keys

Bug heading:

| Key   | Command                            |
|-------+------------------------------------|
| =RET=   | Open the bug in a dedicated buffer |
| =w=     | Copy the short id                  |
| =W=     | Copy the full id                   |
| =C-c r= | Copy =refs/bugs/<full-id>=           |
| =x=     | Toggle open/closed                 |
| =c=     | Add a comment                      |
| =l=     | Edit labels                        |

Bugs heading:

| Key | Command                        |
|-----+--------------------------------|
| =n=   | Create a bug                   |
| =s=   | Set scope (open, closed, all)  |
| =l=   | Filter by label                |
| =a=   | Filter by author               |
| =S=   | Set sort order                 |
| =c=   | Clear label and author filters |

Viewer buffer:

| Key | Command                      |
|-----+------------------------------|
| =g= | Re-read the bug from storage |
| =x= | Toggle status                |
| =c= | Add a comment                |
| =l= | Edit labels                  |
| =w= | Copy short id                |
| =W= | Copy full id                 |
| =q= | Quit                         |

The viewer buffer reads git-bug storage, not a file, so
=revert-buffer= and =revert-buffer-quick= re-read the bug as =g= does.
The compose buffer uses =C-c C-c= to submit and =C-c C-k= to cancel.
A prefix argument on =w= copies the full id or ref.

** Filtering, sorting and grouping

=git-bug-status-section-scope= selects =open=, =closed= or =all= bugs.
=git-bug-status-section-label= and
=git-bug-status-section-author= narrow the list.
=git-bug-status-section-sort= orders by =edit-time=, =create-time=,
=title=, =status=, =label= or =id=.
The =label= order ranks bugs with =git-bug-status-section-label-order=,
an ordered list of regexps that each match one label, or of conses
of a regexp and a capture group number; a rule's position decides
the bucket and its capture group decides the order inside it.
With =git-bug-status-section-group-by-status=, the =all= scope splits
into Open and Closed groups.

** Performance

The section heading uses only the list JSON.
Details load lazily on expansion and cache by repository, full id and
edit time.  An explicit refresh bypasses the cache.
Subprocesses run with quiet git settings and UTF-8 coding.
Explicit writes refresh the status section and an open viewer buffer.

* Library

The status section is one consumer of a small public surface, so these
functions work outside Magit too.

| Function                             | Result                            |
|--------------------------------------+-----------------------------------|
| =git-bug-list= REPO [FILTERS]          | Bugs, filtered, sorted and scoped |
| =git-bug-get= REPO ID [FORCE]          | One full bug                      |
| =git-bug-field= BUG NAME               | One value of a bug, by name       |
| =git-bug-format-bug= BUG [FACES]       | One heading line as text          |
| =git-bug-format-bug-list= BUGS [FACES] | Every heading line, aligned       |
| =git-bug-buffer= REPO ID [MODE]        | A viewer buffer, not selected     |
| =git-bug-show= REPO ID [MODE]          | Show that buffer                  |
| =git-bug-forget= [REPO] [ID]           | Drop cached bugs                  |
| =git-bug-error-data= ERR               | Context of a failed call          |

Answers keep the shape of the git-bug JSON, so no accessor hides the wire.
=git-bug-list= carries a =comments= count and =git-bug-get= a =comments=
list whose first element is the bug description.
=git-bug-field= reads a key by name, ignoring case.
=git-bug-forget= takes a full id or the short =human_id= of a heading.

=FILTERS= is a plist, and a nil value keeps the customizable default:
=:scope=, =:label=, =:author=, =:sort= and =:label-order=.

Calls block Emacs while git-bug runs; there is no async variant.
Cached details live in a hash table keyed by repository, full id and edit
time, and are served while =git-bug-detail-ttl= allows.
A write, a forced read or =git-bug-forget= reports one plist per change
through =git-bug-change-functions=, after the section and the open
viewers have refreshed themselves; a fetch that returns the cached
content reports nothing.
An =invalidate= event from =git-bug-forget= carries no new answer, so a
view of that bug keeps its text and re-reads storage on its next refresh.

Failures signal a subtype of =git-bug-error=:
=git-bug-call-failed=, =git-bug-missing-program=,
=git-bug-invalid-output= or =git-bug-invalid-argument=.
=git-bug-error-data= returns the arguments, exit status and stderr of
the call.

* Requirements

- Emacs 31.1
- Magit 4.0
- =git-bug= 0.11 or newer (its path is baked in when built with Nix)
- optional: the tree-sitter grammars =markdown= and =markdown-inline=
  (=M-x treesit-install-language-grammar=; for Markdown fontification
  of bug bodies)

* Customization

| Variable                               | Default   | Purpose                          |
|----------------------------------------+-----------+----------------------------------|
| =git-bug-program=                        | =git-bug=   | Executable                       |
| =git-bug-status-section-scope=           | =open=      | Which statuses to list           |
| =git-bug-status-section-label=           | =nil=       | Label filter                     |
| =git-bug-status-section-author=          | =nil=       | Author filter                    |
| =git-bug-status-section-sort=            | =edit-time= | Sort order                       |
| =git-bug-status-section-label-order=     | =nil=       | Rules ranking bugs by label      |
| =git-bug-status-section-group-by-status= | =nil=       | Group the all scope              |
| =git-bug-status-section-show-empty=      | =t=         | Show an empty Bugs section       |
| =git-bug-status-section-show-errors=     | =t=         | Show an unavailable Bugs section |
| =git-bug-status-section-verbose=         | =nil=       | Echo CLI failures                |
| =git-bug-detail-ttl=                     | =nil=       | Lifetime of a cached detail      |
| =git-bug-change-functions=               | =nil=       | Hook run on bug changes          |

A repository without git-bug refs and without a git-bug cache stays
untouched.

* Building

#+begin_src sh
nix build          # byte-compile (warnings as errors) + ERT suite
nix flake check    # package + tests + checkdoc + package-lint
nix fmt            # format via treefmt
#+end_src

The ERT suite drives the real =git-bug= binary inside throwaway
repositories, so =git= and =git-bug= are needed during the build.
The dev shell provides Emacs with Magit and exports
=MARKDOWN_GRAMMARS= with the tree-sitter grammars for Markdown
fontification.  For ad-hoc tests:

#+begin_src sh
nix develop
emacs -Q --batch -L . -L test \
  --eval '(setq treesit-extra-load-path (list (getenv "MARKDOWN_GRAMMARS")))' \
  -l test/git-bug-test.el -f ert-run-tests-batch-and-exit
#+end_src
